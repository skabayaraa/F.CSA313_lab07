## Хэсэг E: Дүгнэлт (debrief)

Хамгийн үр дүнтэй аялал нь Couch Potato байсан: хоосон оролтоор хоосон талбартай ном нэмэгдэхийг (BUG-06), он хоосон үед `0` болохыг, `abc` оруулахад `NaN` харагдахыг (BUG-01) хурдан илрүүлсэн. Saboteur аялалд curl-ээр буруу биетэй POST илгээхэд сервер 400 биш `200 OK` буцаасныг (BUG-02) олсон, тасархай JSON дээр ч мөн адил байсан. Гэхдээ `/ghost` хуудас зөв 404 буцаасан. Давхардал (BUG-03), том/жижиг үсгийн хайлт (BUG-04), `<b>` тэмдэгт (BUG-09), урт гарчиг (BUG-10) зэргийг спецификацийн дүрэм бүрийг нэг нэгээр нь хилийн утгаар шалгах замаар олсон. Charter-т бичээгүй боловч санамсаргүй олдсон зүйл бол «Нийт ном» тоолуурын зөрүү (BUG-07), устгах мессеж (BUG-08), оны `2,026` формат (BUG-11) болон устгах товчийн ногоон өнгө юм. Шалгагдаагүй үлдсэн зүйлс: бүх хуудас, линкийн ажиллагаа, мессежүүдийн үсгийн алдаа, зөвхөн гарчиг эсвэл зөвхөн зохиолч хоосон үеийн тусдаа хувилбарууд, API дээрх бусад хүсэлтүүд (зөв JSON боловч буруу талбар, байхгүй id). Эдгээрийг дараагийн session-ий charter болгож болно. Playwright автомат тест API статус 400 (BUG-02), оны муж (BUG-01), давхардал (BUG-03), хайлтын том/жижиг үсэг (BUG-04), хоосон талбар (BUG-06), тоолуур (BUG-07) зэрэг спецификацид тодорхой дүрэмтэй согогийг барих байсан. Харин ногоон устгах товч, урт гарчигаас үүссэн хүснэгтийн тэлэлт (BUG-10), `&lt;b&gt;` харагдах байдал, устгах мессежийн утга зүйн зөрүү зэргийг хүн нүдээрээ харахад илүү амархан олдог.
